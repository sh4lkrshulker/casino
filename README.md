# GIFT GALAXY

Учебный сайт про коллекционирование цифровых подарков: кейсы с виртуальными звёздами, коллекция предметов, ежедневные бонусы, задания и профили игроков.

**Это не Telegram-приложение и не азартная игра.** Звёзды и предметы существуют только внутри демо-проекта: нет оплаты, настоящих Telegram Stars, NFT в блокчейне, торговли или вывода средств.

## Запуск демо

Требуются Node.js 20+ и npm:

```bash
npm install
npm run dev
```

Без настроенного Supabase сайт работает локально в браузере: создай профиль и получи стартовые 300 виртуальных звёзд. Открывай бесплатные демо-кейсы, забирай ежедневный бонус, проходи задания и собирай коллекцию. Локальные демо-аккаунты и их данные не синхронизируются между браузерами; демонстрационный пароль сохраняется только в локальном хранилище.

## Подключение Supabase

1. Создай проект в [Supabase](https://supabase.com/).
2. В SQL Editor выполни [`supabase/schema.sql`](./supabase/schema.sql), затем [`supabase/gifts.sql`](./supabase/gifts.sql).
3. В Authentication → Providers → Email отключи подтверждение email. В URL Configuration настрой адрес сайта и Redirect URLs.
4. Для локального запуска Vite ожидает `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в `.env.local`. Если ключи выданы под именами `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, скопируй их значения в соответствующие переменные `VITE_` из `.env.example`. **Не используй `service_role` key во фронтенде или настройках GitHub.**
5. Перезапусти dev-сервер после изменения `.env.local`.

В форме используется имя и пароль; для Supabase Auth имя преобразуется в технический адрес на зарезервированном домене `.invalid`. Он не получает почту. При включённом подтверждении email регистрация не сможет войти без настройки подтверждения.

Открытие кейса и списание виртуальных звёзд, выдача случайного предмета и проверка заданий выполняются серверными SQL-функциями. RLS закрывает коллекцию и историю наград от других игроков. Клиент не может сам начислить звёзды или подделать находку. Профили сообщества публичны.

Каталог, цены и шансы представлены только как учебная механика; предметы не являются реальными Telegram-подарками или NFT. В проекте намеренно нет пополнения баланса, продажи и обмена предметов.

## GitHub Pages

1. Загрузи проект в GitHub.
2. В Settings → Pages выбери **GitHub Actions** как источник публикации.
3. Для Supabase добавь в Settings → Secrets and variables → Actions → Variables (именно эти имена использует GitHub Actions; префикс `NEXT_PUBLIC_` не подходит):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. Отправь изменения в ветку `main`. Workflow **Deploy to GitHub Pages** соберёт и опубликует сайт.

Если variables не заданы, на Pages останется доступен локальный демо-режим. Этот режим сохраняет данные посетителя в его браузере и не даёт общего хранилища между игроками.
